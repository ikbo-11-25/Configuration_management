# Практическая работа №1. Вариант 30

Графический эмулятор UNIX-подобной оболочки на Python и Tkinter.
Реализованы все пять этапов: REPL, конфигурация, VFS, основные и
дополнительные команды. Источник VFS - директория на диске.
После загрузки команды работают с копией файловой системы в памяти.
Удаление файлов и смена владельца не изменяют исходную директорию.

## 1. Требования и запуск

Нужен Python 3.10 или новее с Tkinter. Сборка, установка пакетов через
pip и доступ к интернету не требуются. В стандартном установщике Python
для Windows должен быть включен компонент Tcl/Tk. На Linux нужен
системный пакет Tkinter и графическая сессия для оконного режима.

В Windows откройте папку проекта и запустите `run.bat` двойным щелчком
или из терминала. В Linux/macOS используйте `sh run.sh`.

```bat
run.bat
```

По умолчанию загружается `examples/vfs/deep`. В окне есть журнал
диалога и отдельное поле ввода. Enter или кнопка «Выполнить» запускают
команду. Заголовок `Эмулятор - [username@hostname]` содержит реальные
имя пользователя и имя компьютера. Команда `exit` закрывает окно.
Ошибки интерактивных команд не закрывают приложение.

Если команда `python` недоступна, в PowerShell можно использовать
установленный Python через launcher:

```powershell
$env:PYTHONPATH = 'src'
py -3 -m emulator
```

## 2. Настройки

| Параметр | Назначение и значение по умолчанию |
| --- | --- |
| `--vfs PATH` | Физическая папка VFS; по умолчанию examples/vfs/deep. |
| `--startup PATH` | Стартовый UTF-8 сценарий; по умолчанию отсутствует. |
| `--headless` | Выполнить сценарий без окна; требует --startup. |
| `--help` | Показать справку и завершиться. |

Физические относительные пути разрешаются относительно рабочей папки.
Скрипты `run.bat` и `run.sh` сначала переходят в папку проекта.
Пути с пробелами в параметрах ОС заключайте в кавычки.
Параметры показываются при запуске и по команде `conf-dump`:

```text
vfs=абсолютный путь к источнику
startup=абсолютный путь к сценарию или (none)
headless=false
```

Пример запуска с параметрами:

```bat
run.bat --vfs examples\vfs\deep --startup examples\scripts\success.txt
```

Тот же сценарий без окна:

```bat
run.bat --vfs examples\vfs\deep --startup examples\scripts\success.txt --headless
```

Для Linux/macOS аналогичны `sh run.sh`, пути с `/` и те же параметры.
Коды завершения: 0 - успех; 1 - ошибка загрузки VFS или сценария;
2 - неправильные параметры командной строки. В GUI ошибка стартового
сценария оставляет окно открытым для исправления команд вручную.

## 3. Команды и поддерживаемые режимы

| Команда | Поведение |
| --- | --- |
| `ls [PATH ...]` | Список содержимого каталога или имя указанного файла. |
| `ls -a` | Добавить скрытые файлы и записи `.` и `..`. |
| `ls -l` | Виртуальные права, владелец, группа, размер, дата и имя. |
| `ls -al`, `ls -la` | Совместить оба режима. |
| `cd [PATH]` | Перейти в каталог; без аргумента - в корень /. |
| `cd -` | Вернуться в предыдущий каталог и вывести его путь. |
| `cal` | Календарь текущего месяца. |
| `cal MONTH YEAR` | Календарь заданного месяца. |
| `cal YEAR` | Календарь всего заданного года. |
| `cal -y [YEAR]` | Календарь всего года; без YEAR - текущего. |
| `who` | Сессия эмулятора: пользователь, время запуска, хост. |
| `rm PATH ...` | Удалить файлы из VFS в памяти. |
| `rm -r PATH ...`, `rm -R PATH ...` | Удалить каталоги с содержимым. |
| `rm -f PATH ...` | Игнорировать отсутствие файлов. |
| `rm -rf PATH ...`, `rm -fr PATH ...` | Совместить удаление дерева и -f. |
| `chown OWNER PATH ...` | Изменить виртуального владельца. |
| `chown OWNER:GROUP PATH ...` | Изменить владельца и группу. |
| `chown -R OWNER[:GROUP] PATH ...` | Изменить метаданные всего дерева. |
| `conf-dump` | Вывести параметры в формате ключ=значение. |
| `exit` | Завершить сеанс; аргументы не поддерживаются. |

В `ls`, `cd`, `rm`, `chown` поддержан разделитель `--`: последующие
аргументы считаются операндами, даже если начинаются с `-`.
Например, `rm -- -file`. Допустимы объединенные короткие опции.
`cal` принимает месяц 1..12 и год 1..9999. Неделя начинается в
воскресенье; названия месяцев и дней выводятся по-английски.

`ls` сортирует имена и выводит их по одному на строку; каталоги
помечаются `/`. Размер файла - число байтов. Для каталогов размер 0.
Права моделируются: 0755 для каталогов, 0644 для файлов.
При загрузке владелец узла - текущий пользователь, группа - `users`;
дата берется из исходного файла. `chown` принимает виртуальные имена
из букв, цифр, `_`, `.`, `-`, без обращения к системной базе пользователей
и без запроса административных прав.

## 4. VFS, парсер и обработка ошибок

Корень `/` обозначает загруженную папку, а не корень реальной ОС.
Поддерживаются абсолютные и относительные UNIX-пути, повторные `/`,
`.` и `..`. Переход выше корня оставляет путь равным `/`.
Исходные файлы читаются как байты; двоичное содержимое тоже сохраняется.
Символические ссылки, junction и специальные файлы не поддерживаются.
Отсутствующий источник, источник-файл или ошибка чтения прерывают запуск.

По условию парсер разделяет ввод по пробельным символам. Кавычки,
экранирование, имена с пробелами в командах эмулятора, переменные,
маски `*`, конвейеры и перенаправления не реализованы. Физические пути
в параметрах запуска с пробелами поддерживаются средствами оболочки ОС.
Ввод не передается командному интерпретатору реальной ОС.

Ошибки возвращаются как `команда: описание`. Проверяются неизвестные
команды, опции, число аргументов, календарные даты, отсутствие пути
и переход в файл. Неудачный `cd` сохраняет состояние каталогов.
`rm` защищает корень, `.`/`..`, текущий каталог и его предков.
`-f` не отменяет эти проверки и не позволяет удалять папки без `-r`.
Несколько операндов `rm`/`chown` обрабатываются последовательно:
при ошибке ранее выполненные изменения в памяти не откатываются.

`who` показывает сессию самого эмулятора с реальными данными ОС.
Другие системные сеансы пользователей не перечисляются.
Права доступа не проверяются; владельцы и группы - состояние VFS.
При новом запуске все изменения в памяти сбрасываются.

## 5. Стартовые сценарии и демонстрации

Сценарий - текстовый файл UTF-8, одна команда на строку. Допустим BOM.
Пустые строки и строки, начинающиеся с `#` после пробелов, пропускаются.
Каждая команда отображается с приглашением, за ней следует ответ.
Первая ошибка останавливает сценарий с указанием номера строки.
`exit` также останавливает выполнение. Строки после остановки
не исполняются; независимые ошибки вынесены в разные файлы.

| Сценарий в examples/scripts | Проверка |
| --- | --- |
| `stage2.txt` | Конфигурация, ls, cd, exit. |
| `stage2-error.txt` | Ошибка conf-dump и остановка сценария. |
| `stage3.txt` | VFS, пути, режимы ls/cd и ошибка. |
| `stage4.txt` | Все режимы ls/cd/cal, who и неверный cd. |
| `stage4-cal-error.txt` | Неверный месяц календаря. |
| `stage4-ls-error.txt` | Неподдерживаемая опция ls. |
| `stage5.txt` | Все режимы rm/chown и защита корня. |
| `stage5-chown-error.txt` | Неверный формат владельца/группы. |
| `stage5-rm-error.txt` | Удаление папки без рекурсивного режима. |
| `success.txt` | Успешный проход всех команд и завершение. |

Скрипты реальной ОС находятся в `examples`: `demo-config.bat`,
`demo-vfs.bat`, `demo-core.bat`, `demo-mutations.bat` и аналоги `.sh`.
Они вызывают эмулятор с параметрами и отдельными сценариями.
Часть вызовов намеренно завершается с ошибкой. Вызовы с GUI выполняются
последовательно: закройте окно или введите `exit`, чтобы продолжить
следующий вызов скрипта ОС.

`demo-vfs` использует три источника: `minimal` с одним файлом,
`files` с несколькими файлами и `deep` с тремя уровнями каталогов:
`docs/course/tasks/task.txt`. Есть вызов с отсутствующим источником.

Пример интерактивного диалога:

```text
/ $ ls
docs/
hello.txt
tmp/
/ $ cd docs/course/tasks
/docs/course/tasks $ ls
task.txt
/docs/course/tasks $ cd /
/ $ chown -R student:course docs
/ $ rm tmp/cache.txt
/ $ ls tmp
/ $ cd missing
cd: no such file or directory: /missing
/ $ exit
```

## 6. Проверки

Windows PowerShell, из корня проекта:

```powershell
$env:PYTHONPATH = 'src'
python -m unittest discover -s tests -v
```

Linux/macOS:

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Проверяются парсер, конфигурация, остановка сценария, загрузка байтов,
разрешение путей, команды и их ошибочные режимы. Отдельный тест
сравнивает содержимое, структуру и метаданные исходной папки до и
после `rm` и `chown`. Тест GUI создает настоящие виджеты Tkinter,
проверяет заголовок, отправку команды и показ ошибки.
При отсутствии графической сессии только этот тест пропускается.
Временные данные тестов создаются в игнорируемой папке `.test-work`.

## 7. Структура и функции

```text
src/emulator/       приложение
tests/             автоматические проверки
examples/scripts/  сценарии эмулятора
examples/vfs/      три примера источника VFS
examples/demo-*.bat и .sh  демонстрации из реальной ОС
run.bat, run.sh     запуск из папки проекта
README.md          документация
.gitignore         исключение служебных файлов
.gitattributes     правила переноса строк
```

Описание функций и классов приложения:

- `parser.py`: parse_command(line) разделяет команду и аргументы.
- `config.py`: Config хранит настройки; dump() выводит ключ=значение;
  parse_config(argv) проверяет параметры и разрешает физические пути.
- `shell.py`: Result хранит вывод, ошибку и exit; Shell.__init__ создает
  состояние и команды; prompt возвращает приглашение; execute(line)
  разбирает и исполняет ввод; conf_dump(args) выводит параметры.
- `gui.py`: Terminal.__init__ создает окно; write(text) добавляет вывод;
  submit(event) исполняет ввод и обновляет приглашение.
- `startup.py`: ScriptStatus хранит результат; run_script(shell, path,
  write) читает, воспроизводит и останавливает сценарий.
- `vfs.py`: Node хранит данные и метаданные; check_source(path) проверяет
  источник; VFS.__init__ создает пустой корень; from_directory(source)
  загружает дерево; get(path, cwd) разрешает путь; _step(parts, node, part)
  проходит один сегмент; _lookup(parts) ищет узел; walk(node) обходит дерево.
  VFSError и MissingPath описывают ошибки VFS.
- `options.py`: CommandError описывает ошибку команды;
  parse_flags(args, allowed) разбирает короткие опции, -- и операнды.
- `commands.py`: long_entry(name, node) форматирует ls -l;
  parse_numbers(values) проверяет числа; CoreCommands.__init__ сохраняет
  оболочку; ls(args) и list_entries(path, node, show_hidden) строят список;
  cd(args) меняет каталог; cal(args) строит календарь;
  calendar_date(flags, values) проверяет дату; who(args) выводит сессию.
- `mutations.py`: parse_owner(value) проверяет OWNER[:GROUP];
  MutationCommands.__init__ сохраняет оболочку; rm(args) и
  remove_one(path, recursive) удаляют узлы; chown(args) меняет метаданные.
- `__main__.py`: main(argv) загружает VFS и запускает интерфейс;
  start_in_gui(terminal) исполняет сценарий в окне.

## 8. Этапы и история Git

Пять последовательных коммитов сохраняют рабочие этапы разработки:

1. `feat(repl)` - GUI, реальные данные ОС, парсер, заглушки ls/cd, exit.
2. `feat(config)` - параметры, сценарий, остановка при ошибке, conf-dump.
3. `feat(vfs)` - загрузка дерева в память, пути, примеры источников VFS.
4. `feat(commands)` - полноценные ls/cd, cal/who, сценарии и тесты.
5. `feat(mutations)` - rm/chown в памяти, проверки и итоговый README.

В первых трех коммитах ls/cd являются заглушками, как предусмотрено
этапами. В итоговом состоянии все команды имеют полноценную логику.
Историю можно просмотреть командой `git log --oneline`.

исключены из Git согласно требованиям оформления.
